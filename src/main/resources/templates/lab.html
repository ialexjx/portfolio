ENGINEERING RFCs & DESIGN SPECS

Architecture Decision Records (ADRs)

Key architectural trade-offs defended during the engineering of the high-throughput FinTech platform.

Context: DigiLocker and eSign were experiencing high thread contention under 100k daily traffic. Sequential PDF downloads and blocking I/O starved platform OS threads.
Decision: Adopted Java 25 Virtual Threads (Project Loom) over Spring WebFlux reactive mono/flux pipelines.
Rationale: Preserves synchronous, readable debugging call stacks while allowing millions of lightweight virtual threads (~300 bytes each) to unmount during I/O blocking. Slashed latency to 7s without reactive callback complexity.
Context: Concurrent multi-pod eSign token generation caused duplicate vendor requests and eMudhra rate-limiting storms.
Decision: Implemented Redis distributed lock with lease expiration (`SET lock:key value NX EX 30s`) instead of MySQL `SELECT FOR UPDATE`.
Rationale: DB locks block transaction connection pools, degrading overall cluster throughput. Redis mutex acquires in <0.8ms in-memory with automatic TTL expiration, preventing deadlocks if a pod crashes.
Context: Production database accumulated millions of temporary Aadhaar contract blobs, threatening storage thresholds. Direct `DELETE FROM tbl WHERE created_at < ...` caused gap locks and table freezes.
Decision: Engineered an asynchronous purge engine iterating over indexed primary keys in strict chunks of 500 records with micro-sleeps.
Rationale: Eliminates InnoDB next-key locks, keeping live client APIs responsive while achieving blistering 2,500 records/sec purge velocity.
